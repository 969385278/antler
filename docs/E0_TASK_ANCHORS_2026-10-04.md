# C20：固定任务理解锚点诊断（评分前登记）

目的：检验现有 TASK_PROMPT 能否区分明确理解但不遵守、随意回应、认真回应与真正误读。只诊断量尺，不改变 E0 门槛或原回答评分。

助手另写六个情境（预约、文件格式、预算、保密、取件、数量），每题四种回答，共24条。属于助手设计的预期类别，不是人类金标；不读取 trait_eval/test 或改动 data/kit。每组同题比较，刻意保持简短，不能直接推广到320-token模型回答。

固定原 TASK_PROMPT、deepseek-flash 及既有请求配置。连续三轮，每轮独立空缓存、seed 0/1/2 随机顺序、单并发，总计72个逻辑评分请求；网络失败仅允许 Judge 原有重试，评分缺失即报告失败，不补评、不增加轮次。类别不进入评委提示。三轮重复不算72条独立文本。

分析：每轮、每题公布四类原分，公布认真减误读、认真减不遵守、认真减随意三个配对差；公布每条跨轮极差。预定诊断标志：认真>=80且误读<=50为基础区分成功；基础区分成功但不遵守比认真低>10为理解/服从混淆信号；随意比认真低>10为风格混淆信号。只报计数及差值，不把六题推断为总体通过率或正式验收。

停止：72项完成或异常后停止。即使出现混淆，也不能直接改提示、重评历史、拟合 q_task 或宣布 C 通过；需结合真实回答另行决定。全部类别不分离也不能证明原指标正确。运行前提交锚点、脚本、测试；输出来源哈希、乱序身份、原响应、run_meta 和汇总。
